# 立即结算模拟器点击车辆录入设计

## 背景

当前“立即结算模拟”页面通过手填 `点击车辆顺序` 文本运行模拟。这个方式适合批量粘贴，但不适合按录屏逐步拆解。用户希望点击车辆记录方式参考现有“剧本还原”的车辆批次记录和“车位记录”的车位状态展示：点击车辆后自动进入最靠左空车位，并能看到每步模拟后的车位、传送带和日志。

## 目标

把“点击车辆顺序”从纯文本输入升级为可点击录入：

- 解析车辆数据表后生成车辆按钮。
- 点击车辆按钮会追加该车辆 id 到点击序列。
- 每次点击后自动运行立即结算模拟。
- 页面显示当前 4 个车位状态、当前传送带、补充队列剩余数量和步骤日志。
- 保留点击顺序文本框，支持粘贴、复制和批量编辑。
- 支持撤销上一步、清空点击记录、删除某一步后重新模拟。

## 非目标

本次不恢复复杂截图能力：

- 不使用停车场截图。
- 不使用 OCR。
- 不使用热区选车。
- 不做真实时间推进或连续快速点击后的时间差模拟。
- 不校验停车场深度、前后依赖和可点击性。

## 交互设计

### 车辆按钮区

车辆表解析成功后，在模拟页面显示车辆按钮列表：

- 按车辆 id 升序展示。
- 按钮文案格式：`#1 红色4`。
- 颜色值继续使用剧本还原里的 0 基颜色映射。
- 点击按钮后，把车辆 id 追加到 `clickSequenceText`。
- 如果车辆 id 已被点击过，模拟核心会给出重复点击警告；UI 不额外阻止，保留用户真实操作记录。

### 当前状态区

运行模拟后显示：

- 4 个车位状态。
- 当前传送带内容。
- 补充队列剩余数量。
- 当前是否有错误或警告。

车位显示格式参考车位记录：

- 空位显示 `空`。
- 有车显示 `#1 红色4 剩0/4` 或 `#2 蓝色6 剩2/6`。

### 点击日志区

每一步显示：

- 步骤号。
- 点击车辆。
- 进入车位。
- 上客统计。
- 开走车辆。
- 车位状态摘要。
- 传送带摘要。
- 警告。

日志项支持删除某一步。删除后重建点击序列并重新运行模拟。

### 操作按钮

新增按钮：

- `撤销上一步`：删除最后一个车辆 id 并重新运行。
- `清空点击记录`：只清空点击顺序和模拟结果，不清空关卡 id、传送带容量、乘客队列和车辆表。
- `运行模拟`：保留现有能力，用于手动编辑文本后重新运行。
- `复制报告`：保留现有能力。

## 数据模型

继续复用现有 `simulation.clickSequenceText` 作为权威点击序列文本，不新增复杂历史结构。

新增纯函数建议：

```js
function appendStableSimulationClick(state, vehicleId) {}
function undoStableSimulationClick(state) {}
function deleteStableSimulationClickAt(state, index) {}
function clearStableSimulationClicks(state) {}
```

这些函数只修改 `clickSequenceText`，然后调用现有 `runStableSimulationState()` 得到最新结果。

## 错误处理

- 车辆表未解析或有错误时，车辆按钮区显示错误提示。
- 点击不存在车辆按钮不会发生，因为按钮只从合法车辆表生成。
- 文本框中手动输入不存在车辆 id 时，沿用现有模拟核心错误。
- 删除、撤销、清空点击记录后，报告和状态必须同步更新，不能保留旧结果。

## 测试计划

- 车辆表解析后可生成车辆按钮数据。
- 点击车辆按钮会追加 id，并自动运行模拟。
- 撤销上一步会删除最后一个 id，并重新运行。
- 删除指定步骤会重建序列并重新运行。
- 清空点击记录只清空点击序列和结果，不清空基础输入。
- 手动编辑点击顺序文本后运行仍可用。
- 原有“立即结算模拟”核心测试继续通过。

## 通过标准

- 用户可以不手写点击序列，直接点车辆按钮完成录入。
- 仍然可以粘贴点击序列文本批量导入。
- 每次点击后立刻看到车位、传送带和日志变化。
- 不影响乘客队列录入、车位记录、剧本还原和现有立即结算模拟报告。
