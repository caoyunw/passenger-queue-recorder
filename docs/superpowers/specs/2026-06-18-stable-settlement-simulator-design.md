# BusLoop 立即结算模拟器 v1 设计

## 背景

现有“剧本还原”工具已经支持乘客队列、车辆表、截图热区和操作批次记录，但截图/OCR/热区流程对第一版分析来说过重。v1 改为结构化输入驱动的模拟器：用户提供完整乘客队列、传送带容量、车辆数据表和点击车辆顺序，工具按固定规则自动推演每次点击后的上客、开走、车位和传送带状态。

## 目标

v1 只支持“点击一辆车后立即结算到稳定”的模式，用来生成一份可解释的基线剧本模拟结果。

模拟器需要回答：

- 每次点击的车辆进入哪个车位。
- 本次结算中哪些车辆吃了多少乘客。
- 哪些车辆满员开走。
- 每次结算后的 4 个车位状态。
- 每次结算后的传送带内容和后续队列剩余数量。
- 是否出现车位满、无可上车乘客的失败/卡死状态。

## 非目标

v1 不处理以下情况：

- 点击之间的真实时间间隔。
- 快速连续点击多辆车后再统一结算。
- 逐帧传送带运动。
- 停车场截图、OCR、热区选车。
- 车辆深度、前后依赖关系和停车场可点击性校验。

这些内容可以在基线模拟器稳定后再作为 v2 扩展。

## 输入

### 关卡信息

- 关卡 id：自由文本。
- 传送带容量：正整数。

### 乘客队列

用户粘贴完整乘客队列配置，格式为逗号分隔颜色值，例如：

```text
0,0,0,2,2,1,1,3
```

模拟器使用传送带容量从队列头部切出初始传送带，剩余部分作为补充队列。

### 车辆数据表

沿用已有车辆表解析能力，但 v1 只依赖：

- 车辆 id
- 车颜色
- 车座位

颜色值按剧本还原规则从 0 开始。

### 点击车辆顺序

用户输入车辆 id 序列，例如：

```text
12,5,8,3
```

每个 id 表示玩家点击一次对应车辆。

## 模拟规则

### 车位规则

- 固定 4 个车位。
- 点击车辆后，车辆进入最靠左的空车位。
- 如果没有空车位，本次点击记录为失败，模拟可以继续保留当前状态供用户检查。
- 同色多车同时在车位时，靠左车位优先上客。

### 立即结算到稳定

每次点击后执行自动结算循环：

1. 扫描当前传送带，从出口顺序开始检查乘客。
2. 如果乘客颜色有对应车位车辆，乘客上车。
3. 上车时选择同色车辆中车位最靠左且仍有剩余座位的车辆。
4. 乘客上车后，该传送带格位变为空位。
5. 有空位时，从补充队列头部补入乘客，保持传送带容量不变。
6. 车辆满员后立即开走，释放车位。
7. 重复以上过程，直到当前传送带中不存在任何可以上车的乘客。

v1 不模拟环形跑道的时间差，因此“出口顺序”采用当前传送带数组从左到右的固定顺序。每一轮扫描都从数组头部重新开始，保证结果稳定、可复现。

## 输出

每次点击生成一条模拟日志：

- 步骤号。
- 点击车辆。
- 进入车位。
- 上客统计，例如 `#12红色4: 3/4`。
- 开走车辆。
- 车位状态，例如 `1:空 | 2:#5蓝色6 剩2 | 3:空 | 4:空`。
- 传送带状态。
- 补充队列剩余数量。
- 警告信息。

工具同时提供一份总览：

- 总点击数。
- 成功进车数。
- 开走车辆数。
- 未开走占位车辆。
- 剩余乘客统计。
- 失败/卡死步骤列表。

## UI 设计

新增一个独立区域“立即结算模拟”，不复用截图热区。

页面结构：

- 左侧输入区：关卡 id、传送带容量、完整乘客队列、车辆数据表、点击车辆顺序。
- 中间操作区：解析/运行模拟、清空、复制报告。
- 右侧结果区：步骤时间线、当前车位状态、当前传送带状态、警告。

为了降低复杂度，v1 只做文本输入和文本结果，不做拖拽、截图或可视化车位编辑。

## 数据模型

新增模拟输入：

```js
{
  levelName: string,
  conveyorCapacity: number,
  passengerQueueText: string,
  vehicleTableText: string,
  clickSequenceText: string
}
```

模拟状态：

```js
{
  belt: number[],
  reserveQueue: number[],
  slots: Array<null | {
    vehicleId: number,
    colorValue: number,
    capacity: number,
    remaining: number
  }>,
  logs: SimulationStep[]
}
```

## 校验与错误处理

- 传送带容量必须是正整数。
- 乘客队列必须至少包含传送带容量数量的乘客。
- 点击车辆 id 必须存在于车辆表。
- 车辆座位只接受 `4 / 6 / 10`。
- 车辆颜色按 0 基颜色映射校验。
- 点击时无空车位时给出警告，不隐式丢弃当前状态。
- 结算循环需要设置安全上限，防止异常数据导致死循环。

## 测试计划

- 解析完整乘客队列并按容量切分初始传送带和补充队列。
- 点击单辆可满员车辆后，车辆上客并开走。
- 点击单辆无法满员车辆后，占用车位并保留剩余座位。
- 同色多车同时存在时，靠左车位优先上客。
- 车辆开走后释放车位，后续点击进入最靠左空位。
- 无空车位时产生警告。
- 传送带无可上车乘客时停止结算。
- 生成可复制的步骤报告和总览报告。

## 通过标准

- 用户只输入结构化文本，不需要截图。
- 同一份输入每次模拟结果一致。
- 模拟报告能解释每一步的车位压力和乘客消耗。
- 现有乘客队列录入、车位操作记录、剧本还原页面不被破坏。
